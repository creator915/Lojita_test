# Dispatcher

## 任务

初期只实现一个无副作用的确定性分流函数；三条路径独立验收后，再添加最小调用适配层。

建议规则：

- 无运行时高阶同伦搬运需求 → `native-binary`
- 需要搬运且跨进程 → `term-transport`
- 需要搬运/计算且在最终程序进程内 → `runtime-nbe`
- 信息缺失、冲突或不支持 → `reject`

## 接口边界

- 输入是版本化分析清单，不重新实现三条路径的语义。
- 分流器只能调用各路径公开接口，不得读取其私有构建目录。
- 分流决策需与源码、入口、依赖和分析器身份绑定；执行前必须复核。

## 验收标准

- 第一阶段用表驱动测试覆盖四种结果，输出稳定理由码；不启动任何路径。
- 集成阶段每次恰好启动一条路径，参数按字面传递，不使用 shell `eval`。
- 身份变化、路径不可用、证据不足和退出异常均 fail-closed，不回退到另一条路径。
- 失败或取消后清理 staging，不删除用户输入，不发布陈旧产物。
- 提供本目录独立测试入口；真实端到端接线只在对应路径独立验收后进行。
